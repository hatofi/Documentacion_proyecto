# HatoFi Vault

The `vault` contract stores the financial state of a cattle batch and the
amount invested by each Stellar address.

## MVP interface

- `__constructor(admin, token_address)` configures the administrator and the
  Soroban token accepted by the vault.
- `create_batch(...)` is restricted to `admin` and stores the financial fields
  of the batch in `DataKey::Batch(code)`.
- `get_batch(code)` reads the persisted batch.
- `invest(investor, code, amount)` requires investor authorization,
  transfers token units into the vault and accumulates
  `DataKey::Investment(code, investor)`.
- `get_investment(code, investor)` reads the accumulated investment.

The batch is keyed by its **code** (a `uuid4` generated by the backend, e.g.
`BATCH-3F2504E04F8941D39A0C0305E82C3301`) and not by the auto-increment id of
the SQL database. The code is stable across database resets or migrations, so
publishing a batch never collides with a batch created before the reset.

The backend and frontend use Testnet for the MVP. SQL amounts use two decimal
places; contract amounts are integer atomic units using the configured token
scale (default `10^7`).

## Project Structure

This repository uses the recommended structure for a Soroban project:

```text
.
├── contracts
│   └── hello_world
│       ├── src
│       │   ├── lib.rs
│       │   └── test.rs
│       └── Cargo.toml
├── Cargo.toml
├── AGENTS.md
└── README.md
```

- New Soroban contracts can be put in `contracts`, each in their own directory. There is already a `hello_world` contract in there to get you started.
- If you initialized this project with any other example contracts via `--with-example`, those contracts will be in the `contracts` directory as well.
- Contracts should have their own `Cargo.toml` files that rely on the top-level `Cargo.toml` workspace for their dependencies.
- Frontend libraries can be added to the top-level directory as well. If you initialized this project with a frontend template via `--frontend-template` you will have those files already included.


# Deploy Paso a paso
<!-- 1. realizar el build -->
```sh
stellar contract build
```
<!-- 1.2 crear una cuenta madre con alias 'alice'-->
```sh
stellar keys generate alice --network testnet --fund
```

<!-- 2. desplegar contrato con token stellar -->
```sh
stellar contract deploy --wasm .\target\wasm32v1-none\release\Vault.wasm --source-account alice --network testnet --alias Vault-hatofi -- --admin alice --token_address CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC
```
